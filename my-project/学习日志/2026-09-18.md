## 1. 选做练习：前端 CDP 通路——沉淀 `/capture-ui` Skill

- **背景**：M6 选做——Chrome 以 `--remote-debugging-port=9222` 启动，让 AI 自己"打开页面 → 截图 → 读控制台 → 定位修复 UI 问题"，并把流程沉淀成 Skill。验收标准：一句话让 AI 拿到「截图 + 控制台报错 + 复现步骤」的结构化报告。
- **改动文件**：
  - `/root/.codebuddy/skills/capture-ui/scripts/cdp-capture.js`（新建，最小 CDP 采集脚本）
  - `/root/.codebuddy/skills/capture-ui/SKILL.md`（新建，Skill 定义）
- **怎么做的**：
  1. **CDP 通路三步**：`GET http://127.0.0.1:9222/json` 拿页面列表 → 用 `webSocketDebuggerUrl` 建 WebSocket → 发 JSON 命令（`Page.navigate` / `Page.captureScreenshot` / `Runtime.evaluate`）+ 收事件（`Runtime.consoleAPICalled` / `Runtime.exceptionThrown` / `Log.entryAdded`）。Node 20 无内置 WebSocket，回退用项目里现成的 `ws` 包（webpack-dev-server 依赖）。
  2. **关键顺序**：先 `Page.enable`/`Runtime.enable`/`Log.enable` 再导航，否则漏掉加载期报错；用导航基准点截断事件数组，避免混入上一页残留。
  3. **Skill 化**：SKILL.md 写清触发词、执行命令、报告 JSON 结构、采集后三件事（看图 → 读报错 → 串源码给结论），让后续会话一句话可复现。
- **过程中发现并修复的三个真实问题**（都是跑验收时暴露的）：
  1. **hash 路由白等 10s**：SPA 同文档导航（`/#/a` → `/#/b`）不触发 `Page.loadEventFired`，要同时等 `Page.navigatedWithinDocument`。且 `Page.navigate` 偶发被浏览器静默忽略（Chrome 刚启动、初始导航未 commit 时），需导航后核对实际 `location.href`，不一致就用 `location.href = url` 兜底。
  2. **截到半透明中间帧**：第一张 system/user 截图里内容区是半透明的 Dashboard——其实是 fade-transform 过渡动画的中间态被截到了。修复：截图前轮询 `[class*=enter-active/leave-active]` 直到过渡结束。
  3. **截图中文全是方框**：容器缺中文字体。`apt-get install fonts-noto-cjk` 后**仍不生效**——运行中的 Chrome 有字体缓存，必须用原参数重启 Chrome（`DISPLAY=:99` + Xvfb）才行。
- **运行/验证结果**：验收达成。一条命令 `node cdp-capture.js --url <页面URL>` 产出 `<name>.png` + `<name>.report.json`（含 meta/screenshot/uiIssues/reproSteps/console/errors/counts）。最终截图：面包屑"Dashboard / 用户管理"、页面内容正确、中文清晰。应用本身控制台干净（0 error），未发现业务 UI bug，修复的三个问题均属"采集通路"自身。
- **收获/知识点**：
  - CDP 的最小模型就是 **HTTP 拿 target + WebSocket 收发 JSON**，不依赖任何 SDK 也能写，`/json` 列表就是"浏览器的目录页"。
  - **无头/虚拟屏环境的截图有三个隐形坑**：同文档导航不触发 load、过渡动画中间帧、缺字体渲染成方框——每一坑都会让"AI 看图诊断"失真，工具必须先把这些消掉，报告才可信。
  - 结构化报告的价值在于**机器可读 + 人可读双份**（`--json` 给程序、摘要给会话），这正是"验收标准一句话"能成立的原因。
  - Skill 的踩坑区是最值钱的部分：这次踩的三个坑全部写进了 SKILL.md"常见问题"，下次会话不会再踩。
- **存疑/待弄懂**：`Page.navigate` 被忽略的确切条件（初始导航未 commit？）没有深究，只做了防御式兜底；多 tab 场景目前靠 `--match` 关键字选页，没有 tab 管理能力。
