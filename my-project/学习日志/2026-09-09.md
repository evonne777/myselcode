## 1. 搭建“学习日志体系”，并用可视化浏览器打开当前项目

- **背景**：想以“边写边问”的方式学习这个 Vue2 项目。需要一套自动记录每次修改/报错的日志体系，同时希望看到 MCP 控制浏览器操作当前程序的效果。
- **本次动作**：
  1. 新建了 `learning-log` 个人 skill（位于 `~/.codebuddy/skills/learning-log/`），约定“每次代码改动后自动向项目根目录 `学习日志/YYYY-MM-DD.md` 追加一条结构化记录”；
  2. 创建了本目录 `学习日志/`（含 `README.md` 说明约定）；
  3. 用 CDP 把可视浏览器（CDP 9222）从另一个项目 `localhost:8081` 导航到当前项目 `http://localhost:8080/`，并点击 Login 验证登录流程。
- **怎么做的 / 命令**：
  ```bash
  # 驱动可视浏览器导航到当前项目（需要 ws 包）
  cd /home/学习/my-project
  NODE_PATH=/home/学习/my-project/node_modules \
    node /root/.codebuddy/skills/live-browser-view/scripts/cdp-drive.js __open__ http://localhost:8080/
  ```
- **为什么出错 / 关键点**：
  - 直接运行 `cdp-drive.js` 报 `Cannot find module 'ws'`：脚本用 `require('ws')`，Node 默认只在脚本所在目录向上找模块，找不到项目里的 `node_modules`。解决：设置 `NODE_PATH` 指向项目 `node_modules`。
  - Chrome 页面 URL 显示 `http://localhost:8080/#/dashboard`：路由是 hash 模式，登录成功后落到 dashboard。
- **运行/验证结果**：页面标题 `my-vue2-project`，`#app` 渲染出导航栏；点击 `Login` 后出现“欢迎回来！登录成功！”和“退出登录”，登录流程通了。
- **收获/知识点**：
  - CDP（Chrome DevTools Protocol）+ `ws` 可以直接用 JS 表达式远程操作 Chrome，不需要装额外浏览器驱动；
  - Node 的 `NODE_PATH` 可以临时指定第三方模块查找路径；
  - 这个项目的登录是“一键模拟登录”，点 `Login` 即写入登录态。

## 2. 读懂 Breadcrumb 面包屑组件（发现两处抄写笔误）

- **背景**：跟写 `src/components/Breadcrumb/index.vue` 一遍仍看不懂，请求讲解。
- **组件原理**：面包屑数据来自 vue-router 的 `$route.matched`（从外层到内层的匹配记录），只挑带 `meta.title` 的层渲染；`created` 先算一次 + `watch $route` 路由变化时重算。最后一级/`redirect==='noRedirect'` 显示为灰字不可点，中间级是链接，点击 `handleLink` 跳转。
- **为什么出错（两处笔误）**：
  1. `getBreadcrumb()` 里 `matched.filter(item => item.meta && item.meta.fifle ...)`：`fifle` 拼错，应为 `title`；`fifle` 永远为 undefined → `levelList` 恒为空 → 面包屑啥也不显示。
  2. `pathCompile()` 里 `pathToRegexp.compile|(path)` 多了一个 `|`，应写成 `compile(path)`；否则 `toPath` 变成数字，点中间级链接会报错。
- **额外注意**：项目装的 `path-to-regexp@0.1.12` 没有 `compile` 方法，将来要做带 `:id` 的动态路由面包屑时需升级该包或自行处理参数替换；当前路由无参数页不受影响。
- **验证结果**：待用户自己改第 38 行后刷新验证。
- **收获/知识点**：
  - `$route.matched` 结构、`meta.title` / `meta.breadcrumb` 约定（来自 vue-element-admin 模板思路）；
  - “最后一级不可点、中间级可点”用 `index === levelList.length - 1` 判断；
  - 抄代码最容易错在「看着像但拼错」的字段名与多余符号，报错/不显示时应先复查这类地方。

## 3. 修好 Breadcrumb 不显示：聊天里贴的“原版”≠ 磁盘上的文件

- **背景**：用户坚持“原版代码就是这样、我没抄错”，但页面面包屑就是不显示。
- **排查过程**：
  1. 用 CDP 检查运行中页面：`.app-breadcrumb` 存在，但 `crumbItems = 0`（DOM 里没有任何面包屑项）→ 说明不是组件没挂载，而是 `levelList` 为空。
  2. 对比「用户贴在聊天里的原版」与「项目磁盘文件 `src/components/Breadcrumb/index.vue`」：**两版并不一致**。磁盘文件第 38 行仍是 `item.meta.fifle`、第 49 行仍是 `pathToRegexp.compile|(path)`；原版是 `title` 和 `compile(path)`。
- **为什么出错**：浏览器加载的是**磁盘上**的源码（webpack 实时编译），不是聊天文本。`fifle` 恒为 undefined → 第二次 filter 全滤掉 → `levelList = []` → 面包屑 0 项。
- **怎么修**：把磁盘文件两处改为原版正确写法：
  ```javascript
  // 38 行
  this.levelList = matched.filter(item => item.meta && item.meta.title && item.meta.breadcrumb !== false)
  // 49 行
  var toPath = pathToRegexp.compile(path)
  ```
- **验证结果**：热更新后页面 `crumbItems = 1`，显示灰字 `Dashboard`，正常。
- **收获/知识点**：
  - “我贴的原版没问题” ≠ “项目文件没问题”：排查 bug 要先确认**磁盘上当前文件**的内容，而不是聊天里出现过的那份；
  - 定位“渲染为空”问题的方法：先在 DOM 确认组件在不在（`.app-breadcrumb` 存在），再确认数据是否为空（`levelList`），从而区分“没挂载”还是“数据为空”两类原因。
