# 学习日志 2026-09-16

## 1. 新增 Hello World 页面并注册路由

- **背景**：练习在这个 Vue 2 + vue-router 项目里"新建一个页面"的完整流程（写组件 → 注册路由 → 能访问）。
- **改动文件**：
  - `src/views/hello-world/index.vue`（新建）
  - `src/router/index.js`
- **修改前**：
  ```javascript
  { path: '/dashboard', component: () => import('@/views/dashboard/index'), hidden: true },
  ```
- **修改后**：
  ```javascript
  {
    path: '/hello-world',
    name: 'HelloWorld',
    component: () => import('@/views/hello-world/index'),
    meta: { title: 'Hello World' }
  },
  { path: '/dashboard', component: () => import('@/views/dashboard/index'), hidden: true },
  ```
- **怎么改的**：
  1. 先看 `package.json` 和 `src/views` 目录结构，确认项目是 Vue 2 + Element UI 的中后台结构，页面统一放 `src/views/<功能名>/index.vue`。
  2. 新建 `hello-world/index.vue`，用 `scoped` 样式居中显示内容。
  3. 在 `src/router/index.js` 的 `constantRoutes` 里插入路由，用 `() => import(...)` 懒加载，路径写成独立的一级路由（不嵌套在 Layout 下，页面全屏展示）。
  4. 检查 linter 无报错。
- **遇到的报错**：无。
- **运行/验证结果**：启动后访问 `http://localhost:8080/#/hello-world` 可看到页面（项目是 hash 模式，默认未开 history）。
- **收获/知识点**：
  - 新页面 = `views` 下建组件 + `router` 里注册，两步缺一不可；漏了路由注册组件再写也访问不到。
  - `component: () => import('@/views/...')` 是路由懒加载写法，页面会被打成独立 chunk，按需加载，首屏更快。
  - `@` 是 webpack 配置的路径别名，指向 `src`。

## 2. 概念答疑：Vue Router 的核心心智模型

- **背景**：请 AI 讲解对 vue-router 的理解，作为对项目 `src/router/index.js` 的配套学习。
- **答疑结论**：
  - **本质**：SPA 没有多页面，vue-router 维护一张 `path → component` 映射表，监听 URL 变化，把匹配到的组件渲染到 `<router-view>` 里。
  - **两种模式**：hash 模式（默认，URL 带 `#`，监听 `hashchange`）和 history 模式（URL 干净，靠 `pushState`，但刷新需后端把所有路径回退到 `index.html`，否则 404）。本项目用的是 hash 模式。
  - **嵌套路由**：`children` + 父组件里的 `<router-view>`，实现"Layout 布局 + 内容区"的中后台经典结构。
  - **懒加载**：`component: () => import(...)`，按需加载页面 chunk。
  - **meta**：路由的附带信息，不参与匹配，本项目侧边栏靠 `meta.title`/`icon` 渲染菜单，`hidden` 控制是否显示。
  - **`$router` vs `$route`**：`$router` 是路由器实例（负责 push/replace/go 跳转），`$route` 是当前路由信息（只读，存 params/query/meta）。
  - **动态路由**：本项目 `resetRouter()` 里 `router.matcher = newRouter.matcher` 是权限方案的配套——登录后 `addRoutes` 追加权限路由，登出时重置 matcher 防残留。
  - **导航守卫**：`router.beforeEach((to, from, next) => {...})`，本项目 `src/permission.js` 用它做登录鉴权。
- **收获/知识点**：
  - 心智模型三句话：一个映射表（path→component 渲染到 router-view）、一套钩子（守卫做鉴权）、一个状态对象（`$route`，URL 就是 SPA 的全局状态之一）。
- **存疑/待弄懂**：`permission.js` 里守卫的具体实现逻辑还没细看，下次可以逐行读一遍。

## 3. 概念答疑：git worktree 与 CodeBuddy `--worktree` 并行开发

- **背景**：练习目标"Worktree 并行三开"（三个终端各起一个 CodeBuddy 会话，分别做后端接口、前端页面、单测，体验并行度 = 3 的调度状态）。
- **答疑结论**：
  - **git worktree 本质**：让同一个仓库同时拥有多个工作目录、检出不同分支，共享同一个 `.git` 对象库（磁盘开销小，不像 clone 三份），三个窗口物理隔离互不干扰。
  - **`codebuddy --worktree <名字>` 的实际流程**（官方文档确认）：在 `.codebuddy/worktrees/<名字>/` 建 worktree → 基于远程默认分支自动创建 `worktree-` 前缀分支（如 `worktree-feat-api`）→ 复制 `.worktreeinclude` 列出的本地文件、按配置符号链接 `node_modules` 等 → 切入新目录启动会话。
  - **可配项**：`settings.json` 的 `worktree.symlinkDirectories`（免重复装依赖）；`.worktreeinclude`（语法同 .gitignore，列 `.env` 之类的本地文件）。
  - **清理方式**：退出会话菜单选"删除 Worktree"；或手动 `git worktree remove` + `git branch -D worktree-xxx` + `git worktree prune`。
  - **指定基础分支**：`--worktree-branch origin/develop`（远程）或 `--worktree-branch feature/foo`（本地，保留未推送提交）；不传默认远程默认分支。
- **环境适配**：练习里"确认工具链不在 C 盘"是 Windows 注意点，Linux 下只需确认 git / codebuddy 在 PATH 里。
- **收获/知识点**：
  - worktree 解决"一个仓库只能有一份工作区"的限制；并行开发的冲突隔离是物理层面的（不同目录）。
  - 派完一个窗口的活不要等，立刻去下一个窗口——AI 在跑、人在调度，才是并行度 = 3 的含义。

## 4. 概念答疑：单会话干三件事 vs worktree 并行三开，区别在哪

- **背景**：练习前产生的疑问——"AI 不能在一个会话里并行处理文件吗，为什么非要开三个终端？"
- **答疑结论**：
  - 单会话能做的事：**读操作可真并行**（批量搜索/读文件），但多任务是**串行排队**的，三个任务总耗时相加。
  - 三个根本限制把单会话和多会话区分开：
    1. **执行模型**：一个会话一次只处于一个回合；三个终端是三个独立进程，CPU 真正同时跑，总耗时 ≈ 单任务。
    2. **工作区**：单会话里三个 feature 的改动混在同一个 git working tree，提交时难拆分；worktree 各自独立目录、独立分支。
    3. **上下文**：三个任务的代码挤同一个上下文窗口，注意力分散且容易"串味"；分开会话各自专注。
  - 类比：单会话 = 一人接三单来回切换；三开 = 三人各领一单，用户只当调度员。
  - **前提**：并行要求任务互相独立（前端页面/后端接口/单测正好满足）；有依赖关系的任务并行了也得等。
  - 补充：子代理/团队模式可以派多个 AI，但默认共享工作区，要达到"三开"效果同样需要 worktree 这层物理隔离。
- **收获/知识点**：
  - "一个会话 = 一个上下文 + 一份工作区 + 一条执行流"；并行三开 = 用三个进程 + 三个目录 + 三个上下文同时打开这三个瓶颈。
  - 并行不是目的，任务独立性才是能不能并行的判断标准。
